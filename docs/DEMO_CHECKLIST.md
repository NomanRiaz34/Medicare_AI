# Demo checklist

Use fictional patient inputs only; do not reveal API keys in recordings.

1. Open a fresh session and show the masked key-entry welcome page.
2. Try an invalid key and confirm the main dashboard stays hidden.
3. Enter a valid key privately, acknowledge API usage and connect.
4. Show the connected sidebar, sign-out button, both themes and six answer languages.
5. Submit an empty/invalid form; show a friendly error.
6. Complete an ordinary fictional assessment, display structured results and live narration.
7. Turn off Live explanation, enable Memory cache and submit identical input twice; check the source label.
8. With fictional data and explicit consent, demonstrate SQLite. Explain that cloud files are temporary and stored on the app server.
9. Test Urdu guidance and download a PDF.
10. Record a short symptom description, consent to transcription, correct its text and submit.
11. Show history and urgency analytics. Explain repeats count separately.
12. Show the explicit emergency checklist and immediate local guidance; never wait for AI in a real emergency.
13. Sign out; confirm the welcome screen returns and patient history is gone.
14. On the deployed HTTPS site, repeat microphone, report and fresh-browser-session checks.

Key verification requires metadata access for the configured model. Generation/transcription quota and account permissions are tested when those features are actually used. This checklist records remaining live checks, not results already obtained.
